# lint-and-code-style

Global repo for how linting and code styling should be done for Synatic projects.

## v3 — ESLint 9 flat config (major)

v3 is a **major** release: the shared config moved from eslintrc (ESLint 8) to
ESLint 9 flat config. Consumers must migrate from `.eslintrc.json` to
`eslint.config.js` (see "Adding to your project" below).

Design notes and changes from v2:

-   `lib/index.js` exports a flat config **array** (no longer autogenerated from
    `.eslintrc.json`; the `copy-to-lib.js` script and the root `.eslintrc.json`
    were removed — edit `lib/index.js` directly).
-   `eslint-config-google` was **dropped**: it has no flat-config successor.
    Impact is small — this config already turned off the google rules it relied
    on (`indent`, `max-len`, `require-jsdoc`, `valid-jsdoc`) and
    `eslint-config-prettier` disabled google's stylistic rules anyway.
-   `eslint-plugin-node` (unmaintained) was replaced by its successor
    `eslint-plugin-n`; the `node/*` rule names became `n/*`.
-   `eslint-plugin-import` was replaced by the maintained fork
    `eslint-plugin-import-x` (flat `errors`/`warnings` configs; rule prefix
    changed from `import/` to `import-x/`).
-   All other plugins use their native flat recommended configs — no
    FlatCompat shims: jsdoc (`flat/recommended`), sonarjs, promise
    (`flat/recommended`), security, prettier (`eslint-plugin-prettier/recommended`,
    which keeps `prettier/prettier` as an error).
-   The mocha/node globals of the base config and the `test/**` rule
    relaxations from v2 were carried over unchanged (with the `n/*` renames).
-   The base config is JavaScript-only (`.js`/`.cjs`/`.mjs`), as before.
    TypeScript projects must add their own `typescript-eslint` flat layer on
    top (see "TypeScript projects" below).

## Making changes

Edit `lib/index.js` (base, mocha/node-oriented) or `lib/jest.js` (base + Jest)
directly. You can test changes by adding code to the `./lib-examples/` folder
and running `npm run lint`, which lints this repository with its own shared
config exactly as a consumer would (`eslint.config.js` in the root). Run
`npm test` as well before committing.

Once you have made your changes, commit to `git`, run `npm version <major,minor,patch>`
to increment the version, push to develop and submit a PR as normal.

## Adding to your project

1. Run `npm i -D @synatic/eslint-config-synatic-node` in your project.
2. Install the peer dependencies listed under `peerDependencies` in this
   project's `package.json` (ESLint 9 and the plugin majors).
3. Create an `eslint.config.js` file in your project:

    ```js
    const synatic = require('@synatic/eslint-config-synatic-node');

    module.exports = [...synatic];
    ```

4. Jest projects use the Jest variant instead (base + Jest plugin and globals,
   also still available at the legacy path
   `@synatic/eslint-config-synatic-node/lib/jest`):

    ```js
    const synaticJest = require('@synatic/eslint-config-synatic-node/jest');

    module.exports = [...synaticJest];
    ```

5. Create a `.prettierrc.json` in your project using this repository's version
   of the file, as it is the most up to date.
6. Ensure your `package.json` engines are at least:

    ```json
    "engines": {
        "node": ">=18.18.0",
        "npm": ">=9.0.0"
    }
    ```

7. Ensure your `package.json` has the required scripts:

    ```json
    "lint": "eslint .",
    "lint-fix": "eslint . --fix",
    "lint-errors": "eslint . --quiet",
    "prettier": "prettier . --write"
    ```

## TypeScript projects

This shared config covers JavaScript only, exactly as v2 did. TypeScript
projects (for example `postgres-emulator`) combine it with a
`typescript-eslint` flat recommended layer for their `.ts` files instead of the
old `@typescript-eslint` eslintrc setup:

```js
const synatic = require('@synatic/eslint-config-synatic-node');
const tseslint = require('typescript-eslint');

module.exports = [...synatic, ...tseslint.configs.recommended];
```

That migration is done per project; it is not part of this package.
